# Codex CN API 版优化记录 · 2026-11-17

本轮已在本地分支 `feat/api-codex-ui` 修改真实工程，准备版本为 `0.3.9-cn.6` / versionCode `77`。暂不接入 Claude，保留后续原生 Messages 协议适配空间。当前只支持第三方 HTTPS Responses API。

## 项目基础与源码对应

项目基于 Mobile Codex v0.3.9，Android 原生层使用 Java，聊天界面使用 WebView。随包的 Codex app-server 负责线程、工具和编程代理；模型推理通过在线 API 完成。

现有 V5 APK 来自旧二进制补丁构建，不能直接等同于先前恢复的上游源码。本轮把前端和 API 原生实现放回实际 Android 工程，并新增根目录的源码构建流程。构建将同时输出对应 Git 提交的源码、实际 APK 身份、哈希，逐个核对 APK 内 Web 资源与源码。旧发布的 `source_complete: false` 保持不变。

## 已落地的修改

| 部分 | 原有问题 | 当前源码行为 |
| --- | --- | --- |
| 输入区 | 两排工具，焦点切换改变布局，按钮留白与宽度规则冲突 | 一排“添加 / 模型与思考 / 发送或停止”，主要按钮统一 44px，图标 20px、间隔 8px |
| 项目与模型 | 输入区入口重复、模型名称挤占空间 | 项目放顶部，文件入口集中；输入栏使用简短模型名，面板展示完整 ID 和服务商 |
| 流式输出 | 每次增量触发全量消息绘制和重复高度测量 | 增量按帧合并，仅更新发生变化的消息；键盘与输入高度在同一帧调整，保留阅读历史时的位置和草稿 |
| 动效 | 更新过程重复重建部分节点，反馈不统一 | 保持导航/模型节点，按压与面板使用短时 transform/opacity 动效，尊重减少动画设置 |
| API 启动 | 原上游流程依赖 ChatGPT 登录 | 有效服务商可独立启动，密钥由进程环境注入；设置页不返回已保存的密钥 |
| 服务商切换 | 会话与服务商缺少可靠边界 | 不同服务商及密钥版本隔离运行目录，阻止跨配置恢复远端会话；本地历史保留 |
| 服务商编辑 | 改名称也可能打断现有会话 | 名称/模型列表编辑保留会话；地址、协议或密钥变更才创建新的连接版本 |
| 升级迁移 | 旧 V5 加密配置与新源码格式不同 | 加入旧格式迁移，全部新数据保存后才清理旧密文；失败保留旧数据并显示提示 |
| GitHub 登录 | Android 无法执行下载的 GitHub CLI | 设置页加入浏览器设备授权，凭据由 Keystore 加密保存，Git 通过本地 helper 按需获取 |
| 中文与身份 | 上游包名/版本及中文资源不一致 | 包名 zhcnv3，版本 77 / cn.6，默认中文，更新源指向用户仓库 |

已移除订阅登录及额度组件、Live/WebRTC 实时语音和专属后台服务、音色选择、Pro 网页咨询，以及外部 Claude/Gemini CLI 邀请主流程。保留项目、文件、命令、Git、技能、MCP、审批与 Codex 原生子智能体配置。

系统听写移至“+”菜单：它使用 Android 识别服务，将结果放入草稿，不依赖 ChatGPT 订阅。它与被删除的实时语音对话是不同功能。

GitHub 登录使用用户自己注册并开启 Device Flow 的 OAuth App，仅需公开 Client ID，不依赖 `gh` 或 Client Secret。包含取消、拒绝、过期、退出、迟到网络响应保护和真实账号校验。授权仅接受 `public_repo workflow`，范围涵盖用户可操作的公共仓库，并非 GitHub 服务端的单仓库授权。旧 APK 可先运行一次性 Python 脚本，通过浏览器授权推送当前已提交源码；脚本不持久保存令牌。具体注册和首次构建步骤见 [GitHub 登录说明](GITHUB_LOGIN.md)。

WebRTC 原生依赖也已从构建中移除。当前没有构建出的新版 APK，因此不把资源减少量当成最终 APK 减少量，也不提供未经测量的安装包大小。

Codex 与 code-mode host 是包体中的主要部分，同时承担核心编程能力，本轮保留。Linux 环境原本按需另行下载，删除其入口对当前 APK 大小帮助有限。

## 子智能体、模型与 Claude

本轮三个工作智能体继承本线程 `gpt-6.1-sol`，没有单独设置思考强度；工具未返回实际继承档位。

应用保留 Codex 原生子智能体设置。本机运行时类型探测确认 `multi_agent`、`agents.enabled`、`agents.max_threads` 及旧并发字段别名被识别。设置成功只表示配置写入，不表示已经通过第三方 API 实际调用 `spawn_agent`。

思考档位默认使用“自动”，模型名不再作为能力证明。当前运行时协议接受非空 effort 字符串，`max/ultra` 能通过协议解析，但其模型支持仍未验证；第三方服务商可能拒绝。`/models` 扫描同样只发现模型 ID，不能证明 Responses、工具或思考强度可用。

服务商配置显式保留 `protocol` 字段，当前只接受 `responses`。以后增加 Claude 原生 Messages 适配仍需要实现并测试协议、流式事件、工具与停止处理；本轮不会把设置中的 Claude 名称当成已接入。
