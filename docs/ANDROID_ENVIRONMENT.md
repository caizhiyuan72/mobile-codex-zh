# 手机环境排障记录

2026 年 11 月 19 日核对。在 `upstream-source/` 下运行 `mc-linux` 时，Arch Linux ARM64 内的项目目录是 `/workspace`，与手机终端看到的是同一份源码。工具缓存和临时目录可能变化，使用前探测一次即可。

| 遇到的问题 | 直接采用的办法 | 验证结果 |
| --- | --- | --- |
| 手机终端找不到 `rg` | 从仓库内用 `git grep -n -F -- '文本'` 查 Git 已跟踪的文件。需要查未跟踪文件时，用 `find` 找目录和文件，再用 `grep -nF` 查内容。 | 手机终端已核实没有 `rg`，有 `git`、`find` 和 `grep`。 |
| Wrangler 的 `workerd` 依赖在 Android 原生环境报 `Unsupported platform: android arm64 LE` | 停止在原生环境重试。用 `mc-linux status` 确认可用，从项目目录进入 Linux 后检查 `node`，再安装 Wrangler 并部署。 | 思阶已用 Linux 下的 Node.js 22 和 Wrangler 4.119.0 完成 Cloudflare 部署。 |
| Playwright 在 Android 原生环境报 `Unsupported platform: android`。Linux 下载 Chromium 后缺 `libnss3.so`、`libgbm.so.1` 等依赖，Arch ARM 镜像返回 404 | 在 `upstream-source/` 下用 `mc-linux status` 确认可用，再进入 Linux。用 `/root/sijie-node/bin/node` 运行 Playwright 的 `install --only-shell chromium`，浏览器缓存可设 `PLAYWRIGHT_BROWSERS_PATH=/tmp/dafeilong-playwright`。如果 `chromium.executablePath()` 指向不存在的完整 Chromium，用 `find "$PLAYWRIGHT_BROWSERS_PATH" -type f -name headless_shell` 找已缓存的无头版，将路径传给 `MOBILE_CODEX_BROWSER_EXECUTABLE`。把 Debian ARM64 依赖包内的 `data.tar.*` 用 `bsdtar` 解到 `/tmp/dafeilong-browser-debs/libs`。把该目录下的 `usr/lib/aarch64-linux-gnu` 和 `lib/aarch64-linux-gnu` 加到 `LD_LIBRARY_PATH`，用 `ldd` 检查 Chromium 的共享库。运行截图检查时设置 `FONTCONFIG_FILE=/workspace/app/build/local-check/browser-fonts.conf` 以加载缓存字体。 | 2026-11-22 验证了 `.22` 的四种窗口尺寸。2026-11-23 显式指定缓存的 `headless_shell` 后，`ldd` 未发现缺失的共享库，`.25` 的五种视口均通过布局、玻璃模糊和系统栏交界像素检查。 |
| 手机终端找不到 `java`，需要构建或签 APK | 在 `upstream-source/` 下先用 `mc-linux status` 确认可用，再用 `mc-linux -- /bin/bash -lc '命令'` 进入 Linux。已用的 JDK 是 `/tmp/bloom-jdk`，本地 Gradle 是 `app/build/local-check/gradle-8.13`，本地 SDK 是 `app/build/local-check/sdk`。如果缓存变了，先查 Linux 的 `java` 和项目 SDK 配置。 | 已核实 Linux 是 ARM64，JDK 17、Gradle 启动器和 SDK 35.0.0 的 `aapt2`、`zipalign`、`apksigner` 均在。`0.3.9-cn.12` 已在该环境构建和签名。 |
| Gradle 离线模式找不到依赖或 Android Gradle 插件 | 先复用已准备的本地 Gradle 和 SDK。若已有镜像初始化脚本，传入 `-I app/build/local-check/repos.gradle` 以复用对应缓存。依赖仍缺失时，去掉 `--offline` 重跑当前目标，并检查第一个缺失的依赖。 | LaTeX 更新使用本地镜像缓存成功执行 `assembleFresh`。 |
| Linux ARM64 下 Gradle 找不到 Maven AAPT2，在线模式又因 SDK 源列表连接超时失败 | 复用已验证可执行的 Android SDK AAPT2：`-Pandroid.aapt2FromMavenOverride="$PWD/app/build/local-check/sdk/build-tools/35.0.0/aapt2"`。 | 2026-11-20 在 Linux ARM64 上确认 AAPT2 可运行，并通过 GitHub OAuth 定向单测。 |
| Android 单测出现 `UnsatisfiedLinkError` | 根据报错确认缺哪个原生库及它的架构。若 Linux ARM64 缺 `conscrypt_openjdk_jni-linux-aarch_64`，对不依赖 Conscrypt 的测试可用 `JAVA_TOOL_OPTIONS=-Drobolectric.conscryptMode=OFF` 重跑。完整 Android 单测使用 `.github/workflows/build-android.yml` 的环境。 | LaTeX 更新的两项 WebView 资源路由测试在该参数下通过。2026-11-22 GitHub 授权及权限校验的 27 项定向单测和 `assembleFresh` 也通过。该手机环境的完整 `testFreshUnitTest` 仍未通过验证。 |
| Android 单测报 `The Robolectric native runtime is not supported on Linux (aarch64)` | `-Drobolectric.conscryptMode=OFF` 可用于隔离 Conscrypt 依赖。需要 Robolectric 原生图形库的测试在 CI 的 Linux x86_64 环境运行。手机上可单独运行兼容用例。对 `SafeWebViewLayoutTest` 可用 `--tests 'dev.mobilecodex.app.SafeWebViewLayoutTest.*[29]'` 选中 API 29 用例。 | 2026-11-20 两个变体的对话切换回归、语言回退、后台恢复、Lint 和 APK 打包均通过。全量单测仍有原生图形库不兼容、Linux 未装 Git 和终端输入关闭用例超时。2026-11-22 `.22` 的 WebView 资源路由测试通过，图标解码测试仍受原生图形库限制。2026-11-23 `.25` 的两个 API 29 安全区用例、两个恢复渲染用例和一个 WebView 资源路由用例通过。两个需要原生图形库的安全区用例仍受 ARM64 限制。 |
| Android Python 缺 `lief`，Linux 的 Arch ARM 软件包下载返回 404 | 使用从 `astral-sh/python-build-standalone` 固定发布获取且核对 SHA-256 的 Linux AArch64 Python 3.12，在 Arch Linux 中执行 `python3.12 -m pip install --only-binary=:all: --target <临时目录> -r tools/requirements-devtools.txt`，用 `PYTHONPATH` 指向依赖目录。 | `lief==1.0.0` 的 Linux ARM64 wheel 可用，实际运行时打包契约单测通过。Linux 的完整 Python 测试仍有一项需要未安装的 Linux Git。 |
| 原生终端用 `app_process` 加载 Root 组件测试 APK 时报告 `Runtime library not loaded`，`dalvikvm` 也中止 | 不把 CLI 进程当作已安装应用的运行环境。用 Linux 构建 `:root-files:assembleDebugAndroidTest`，在可安装测试包的设备上走 Android Instrumentation；Root 交互单独使用支持的真机和 Root 管理器确认。 | Linux 已编译测试 APK。本次未安装测试 APK，也未发起 Root 授权。 |
| 当前 App 读不到另一个 App 的私有目录，Arch Linux 也可能读不到手机的下载目录 | 由用户把需要的单个文件放到当前 App 可访问的位置。Linux 读不到下载目录时，从 Android 终端把所需文件复制到私有工作区里用 `mktemp -d` 创建的临时目录。签名后核对证书并清理本次创建的临时副本。需要执行脚本或使用符号链接的构建也放在私有工作区。 | `.12` 和 `.13` 本地签名成功，证书和已安装版一致。`.13` 已核实 Linux 不能直接读签名输入，私有工作区的临时路径可用。 |
| Android 能读取应用自有签名目录，Linux 从项目目录启动时 `test -r` 却读不到该目录下的文件 | 从项目目录用 `mc-linux` 对齐 APK，把 APK 和 `apksigner.jar` 放在 Linux 的 `mktemp -d` 临时目录。将 Android 终端的工作目录切到应用自有签名目录，再运行 `mc-linux`，通过 Linux 的 `/workspace` 就地读取密钥和证书。回到项目目录验签并清理临时文件。 | `.24` 在 Linux ARM64 通过 APK v3 签名、ZIP 对齐和与已安装版的证书比对。私钥仅在原签名目录读取。 |
| 工具拒绝 `rm -rf` 清理临时目录 | 在 `mktemp -d` 创建的目录内，用 `unlink` 只清理本次生成的已知临时文件，再用 `rmdir` 移除空目录。 | `.13` 签名使用了逐一清理临时文件的方法。 |
| 手机终端直接执行缓存中的 `zipalign`、或用硬链接交付时报告 `Permission denied` | 在 `upstream-source/` 通过 `mc-linux` 执行 `zipalign` 和 `apksigner`，回到 Android 终端用 `cp -n` 交付，再核对源文件和交付文件的 SHA-256。 | `.19` 已通过 APK 签名和 ZIP 对齐检查，交付文件的 SHA-256 与签名产物一致。 |
| Android 终端的 `mktemp` 对带扩展名的模板报 `need XXX` | 让模板以 `XXXXXXXX` 结尾。验签时可直接使用无扩展名的临时 APK 副本。 | `.13` 的下载副本以此方法通过验签。 |
| PTY 中 `pm path` 返回空，启动已安装的运行时得到 `ENOENT` | 先在普通 shell 用 `pm path` 获取 APK 路径，再把对应 `lib/arm64/libcodex.so` 的绝对路径传给 PTY 中的探测程序。 | 已验证可通过独立 `app-server` 完成两轮流式对话。 |
| 下载目录和工作区未找到大肥龙原签名材料，GitHub 登录已过期 | 在本机可访问的共享存储里检查文件管理器回收站。用私有临时目录处理找到的原私钥，从已安装 APK 提取并校验公开证书。Linux 未装 `cmp` 时，用 `sha256sum` 比对私钥派生的公钥与证书公钥。 | `0.3.9-cn.19` 的 31 项定向单测、Lint 和 APK 构建通过；已使用原密钥签名，并确认与已安装 `.18` 的证书一致。已核对下载目录中的签名副本。未安装或验证真机横幅。 |
| 中转站的 GitHub 发布附件直链下载超时，Android 原生终端没有 Docker 和 `openssl` | 在 `mc-linux` 中用 GitHub 发布 API 获取附件编号和 SHA-256，再用 `curl -fL -H 'Accept: application/octet-stream' 'https://api.github.com/repos/所有者/仓库/releases/assets/附件编号?download=时间戳'` 下载，先验 SHA-256。用 Linux ARM64 Compose CLI 的 `config --quiet` 校验部署配置。 | 2026-11-23 校验了 Sub2API `0.2.24` 和 Compose `2.40.3` 的 ARM64 下载，测试了配置初始化及权限，两个 Compose 配置和 Caddyfile 均通过。手机没有 Docker daemon。 |
| Arch Linux ARM64 的 PostgreSQL `initdb` 调用 `shmget` 报 `Function not implemented`，PRoot 的 `--sysvipc` 在选择连接数时卡住。Android 原生 PostgreSQL 的子进程也受应用目录执行限制 | 用纯 WASM PGlite 的本地 PostgreSQL 套接字和 Debian ARM64 Valkey 验证 Sub2API 启动。生产部署使用 Linux Docker 及正式 PostgreSQL。 | 2026-11-23 本地验证了数据库迁移、管理员创建、`/health` 返回 200 和匿名 `/v1/models` 返回 401。PGlite 的会话连接导致登录超时。`check-relay.py` 已通过模拟 HTTPS 服务的鉴权及 Responses 流式验证，真实上游转发待联调。 |

普通界面验证可在手机终端从 `upstream-source/` 直接运行 `node --test --test-concurrency=2 tests/*.test.cjs`。命令失败时，先记录实际错误和发生在哪个环境，再把换用的方法及运行结果补到对应条目。替代方法待验证时，标为待验证。

2026-11-23 苹果界面重构复查：Linux ARM64 上浏览器五个套件通过，含原版与液态玻璃的深浅色、取样对比度和模拟键盘。Android `:app:assembleFresh` 与 71 项兼容定向单测通过；扩大范围时有 7 个图片相关用例依赖 Robolectric 原生图形库，需在 Linux x86_64 CI 验证。桌面 Chromium 的视口模拟不替代真机输入法或帧率测试。

GitHub 登录有效且 REST 公开分支查询返回 200，但本机 Git HTTPS 查询出现 `SSL_read: unexpected eof while reading`，强制 HTTP/1.1 也有同样错误。REST 可用于确认远端提交，不代表 Git 上传可用；网络恢复后再走现有凭据助手正常推送，无需禁用证书验证或重新授权。
